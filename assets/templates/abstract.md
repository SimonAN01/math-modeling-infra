# 摘要反写模板

> 摘要是评委看的第一页，也是拿分的头号阵地：**最后反写**（正文、检验、结论全部定稿后），
> 控制在 **4/5--1 页**。2026 规范无需英文翻译。
> 写法细则见 `paper-outline.md` 摘要一节；本模板负责"写之前逐项过"。

## 写作时机（铁律）

1. 各问正文（模型建立与求解）→ 2. 检验与灵敏度 → 3. 结论 → **4. 摘要最后写** → 5. 问题重述 / 分析回填 → 6. AI 工具使用声明 → 7. humanizer-zh 过全文。
   先写正文是为了让摘要里的**每个数字都从正文结果表里抄**，而不是先定数字再让正文去凑。

## 结构模板

```
开头 2--3 句（约 3--5 行）：
  研究对象是什么、这个问题有什么意义、本文的整体工作思路（一句话点全篇技术路线）。

问题一：
  一句话说清这一问要解决什么 → 交代数据/现实条件 → 说明方法与关键建模细节 → 明确给结果。
  （子问题分开讲："第一问……第二问……"，每个子问报自己的方法）

问题二：
  同上。注意：中间过程模型对最终答案有实质支撑的，也在这里点出（如"先经 K-means++
  聚类得到品类分组，再……"），不只报最终模型名。

问题三 / 问题四：
  开放性"软"问题也要报方法（如"文献检索法综合引入 10 种相关数据"），不能一句带过。

结尾 1 句（可选）：
  总结亮点、推广性或整体效果（国一写法示例："最后本文对模型进行了讨论和分析，
  综合评价了模型的优缺点"）。

关键词（4--6 个）：
  核心模型、关键方法、高频主题词。
```

## 逐问段落的内核：报结果，不只报方法

每段按这个顺序写，四件事缺一不可：

| 顺序 | 写什么 | 反例 |
|---|---|---|
| 1 | 这问要解决什么 | 直接跳进方法，评委不知道你在答哪问 |
| 2 | 数据 / 现实条件 | "用神经网络拟合"——没说用什么数据 |
| 3 | 方法 + 关键建模细节 | 只写"建立优化模型"，不写目标、约束的要点 |
| 4 | **明确的结果** | 写"结果较好"而不给数值 |

**结果给法优先级：数值 > 区间 > 规律描述。** 能给 `5105.60 元` 就给，能给 `2.5kg--10kg` 就给区间，
最后才是"销量呈季节性波动"这类定性结论。

## 与正文的三方对账

- [ ] 摘要中每个数字都能在**正文结果表**里找到，一字不差（含小数位）
- [ ] 摘要中每个数字与 `04-results/` 最终结果、提交的结果文件（xlsx）一致
- [ ] 摘要报的方法名与各章标题 / 正文一致（不写论文里没出现的"灰色预测"）
- [ ] 子问题数量与 `question-map.md` 一致，无合并、无遗漏

## 常见错误清单（写完自查）

- [ ] 开头堆空话："随着……的发展，……越来越重要"——改成具体的研究对象与意义
- [ ] 只报模型名不报结果（"运用 XGBoost 进行预测"而后面没有数字）
- [ ] 子问题合并成一段，评委对不上题目小问
- [ ] 报"软"问题方法时一句带过
- [ ] 超过 1 页（2026 规范摘要专用页一页，超页直接改紧凑）
- [ ] 写"本文将……"的预告腔（"本文将建立 X 模型"）——摘要应该报已完成的结果，用过去式叙事
- [ ] 关键词堆砌、与正文无关、数量不足 4 个

## 定稿前最后一关

写完摘要，按 `paper-review.md` 自审清单过一遍摘要相关项，再过 humanizer-zh；
确认首页 `\timu{}`、`\keyword{}` 已替换为真实标题与关键词。
