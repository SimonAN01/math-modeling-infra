# 问题分析

依据 S07、S10。分析说明“为什么这样解决”，正文模型章节说明“具体怎样建立和求解”。

## 内容安排

默认用连贯自然段组织：整体任务与数学类型 → 数据条件与处理理由 → 各问路线和承接 → 验证计划与输出形式。任务跨度大时允许具体的小标题；无需规定“一问恰好一个小节”，但每个子任务都必须可定位。

逐问覆盖六件事：任务目标、数学类型、数据支撑与限制、团队选定路线及理由、输出形式、验证办法。确有比较依据时写备选方法；尚未决定的方案留在 `03-models/method-selection.md`，不在正文中假装已经采用。

数据缺失、异常、相关性、样本规模必须有检查依据。“可能存在”与“已发现”分开。预处理在这里说明必要性与计划，实际处理数量和结果在数据/求解章节给出。不得写尚未完成的检验。

## 框架图

先列节点和箭头，再绘图。节点写输入、方法或输出对象；箭头标注传递的数据、参数、单位或时间尺度。独立问题并列；只有真实使用前问输出才连接。检验反馈可指回模型调整，不能画成每问必然递进的装饰图。

## 可复制提示词

> 读取题面、question-map、真实数据检查、团队确认的路线，撰写问题分析。采用自然段说明各任务数学类型、数据处理理由、模型适用依据、真实依赖、检验计划及所需输出。可用具体小标题，但不要机械按问数拆节。不要给求解结果、权重、排序、误差数值或最终结论，不展开公式推导。另列“节点A—传递对象/口径→节点B”的框架图设计，以及数据事实、路线或依赖尚缺的证据。输出正文和检查记录，保持二者分离。

## 验收

- [ ] 每问均覆盖上述六项，且与实际建模章节一致。
- [ ] 图中的每条依赖有实际输入输出对应；没有虚构联系。
- [ ] 无提前报答案，无重复题意或大段方法教科书介绍。
- [ ] 将计划与完成事实分开，方法改变后已同步改分析与框架图。
