# 题目逐句挖掘方法论

> 拆题机的第 0 步，也是最不能省的一步。**题目的每一句话都有三类价值：要求什么、
> 给出什么、约束什么。** 官方判分证据（calibrations 迁移规则 5）说得直白：
> **题面每个数值操作要求 = 一个评分约束，漏一句 = 少一个评分点。**
> 工作写进 `01-problem/problem-mining.md`；本手册讲怎么挖。

## 〇、逐句三问法

每句话过三遍：

1. **这句话在要求什么？** → 提取成任务/输出要求 → 落 question-map 的"输出"格或 problem-brief 的输出要求
2. **这句话给出了什么信息？** → 数据字段/单位/时间范围/公式/参数 → 落"输入"格、problem-brief 的已知数据
3. **这句话约束了什么？** → 数字、范围、条件 → 落"约束条件"格 + 第三节数字清单

三问都没有收获的句子 → 标注"无需处理"（也可能是干扰句，见下）。**"无需处理"也是结论，必须写明**——这就是不漏句原则。

## 一、七类句子与提取动作

| 类型 | 识别特征 | 提取动作 | 落点 |
|---|---|---|---|
| **背景** | "随着……""近年来……"行业描述 | 提炼 1 句论文背景素材（问题重述章用），标出可引用文献的点 | problem-brief 题目目标 + paper-outline 重述句式 |
| **任务** | "请建立模型""分析""给出""制定" | 拆成主问→小问；每小问写清交付物形式（数值/表格/方案） | 第二节结构表 + question-map 输出格 |
| **数据** | "附件 X 给出了""数据包括"字段名、单位、时间范围 | 逐字段登记；注意缺失/异常说明（"部分缺失"是清洗线索） | question-map 输入格 + data-log 待办 |
| **约束** | 数字 + 限定词（"不低于""不超过""每……"） | 每个数字一条，进数字清单；标注硬/软 | question-map 约束格 |
| **评分线索** | "结果以……形式提交""提交 xlsx""区分工作日/周末" | 这些是评委打分锚点，一个都不能漏 | 数字清单 + 输出格 |
| **提示词** | "必须/不得/建议/可参考/注意/若……则" | 硬约束（必须/不得）进约束；软约束（建议/可参考）标注为加分线索；"注意"多为陷阱提醒 | 第四节提示词清单 |
| **干扰** | 与解题无关的叙述/背景细节 | 标注"无需处理"，防队友反复读它浪费时间 | 逐句表"无需处理" |

## 二、数字敏感原则

- 题面出现的**每个数字都要登记**（数量、阈值、比例、时间窗、范围）
- 每个数字问一句："这是约束？输入参数？还是评分锚点？"——分类后落表
- 官方实证（2023 C）："27--33 个单品""2.5kg 下限""7.1--7.7 区分工作日周末"全是独立评分点

## 三、主问 × 小问结构规则（以题面为准）

> **结构由题面决定，不是由模板决定。** 4 主问 × 每问 1--3 小问只是一般情况；
> 有的题 4 问无小问（2023 C、2025 C），有的题 3 问多要求（2024 C）。**题面说几问就几问。**

1. **主问定方向**：递进规律按题型走（仅一般规律，以题面为准）：
   - 数据驱动题：数据关系 → 核心决策 → 扩展/改进 → 开放建议
   - 机理题（A 类）：机理建模 → 参数辨识/反问题 → 控制/优化
   - 规划调度题（B 类）：确定性规划 → 不确定性/风险 → 耦合扩展
2. **小问定交付物**：有小问时，每个小问 = 一个独立建模段落 + 一份独立交付物；论文里"章内二级标题数 = 小问数"（`modeling-chapter.md` 骨架规则）；**无小问时主问自己就是建模单元**
3. **依赖要写清**：小问之间、主问之间谁喂谁？（"链条关系"格）
4. **建模单元独立十要素**：输入/输出/决策变量/约束/方法/验证/隐含目标/隐含约束/链条/创新候选——有小问按小问填，无小问按主问填
5. 典型结构对照：2023 C 是 4 问无小问；2024 C 是 3 问多要求；2025 C 是 4 问无小问。**拿到题先数清"几问、每问几小问"，再决定填表粒度。**

## 四、提示词敏感表

| 词 | 性质 | 动作 |
|---|---|---|
| 必须 / 不得 / 应 | 硬约束 | 进约束格，答辩必查 |
| 建议 / 可参考 / 如 | 软约束 / 加分线索 | 标注"软"，做进模型是加分项 |
| 注意 / 特别 | 陷阱提醒 | 逐条登记，防止踩坑（如"注意单位换算"） |
| 若……则 | 条件分支 | 拆成条件约束，模型里要有对应分支 |
| 并说明 / 请解释 | 写作要求 | 落"输出"格——**题目要求解释的地方必须写解释段** |

## 五、不漏句原则（执行纪律）

1. 句子按原文顺序编号，逐句过，**不许跳句**
2. 每句必有一个落点，落不进去就写"无需处理"（写明理由）
3. 填完对照原文数一遍编号——少一个编号就是漏了一句
4. 队友交叉核对：建模填的挖掘表，写作对着原文抽查 5 句

## 六、与其他文件的契约

- 挖掘表 → `question-map.md`（每小问十要素）+ `problem-brief.md`（总纲/题型判断）+ `data-log.md`（数据字段待办）
- 跑 `scripts/dismantle <目录>` 校验：小问结构齐全、十要素无空、挖掘表有行、数字清单非空
- 下游建模机只认这个结构：**小问字段名与十要素键名不许改**
