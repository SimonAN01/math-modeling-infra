# 72 小时作战手册

> 比赛期间的执行剧本：谁在什么时候干什么、产出什么、读什么。
> 时间轴按 9.10（四）开赛起算，72 小时交卷。铁律：**每个窗口结束前更新 handoff.md**，
> **每个关键节点跑一次 paper-check**。

## 〇、战前 1 小时（开赛前）

- [ ] 建项目骨架（`init-project`），填 `AGENTS.md` 占位符（拿到题立刻填赛题信息）
- [ ] 三台机器确认：uv 环境、XeLaTeX 编译、GitHub/网盘同步通道、附件数据下载
- [ ] 打印 `checklist.md` 的赛前 48h 清单，逐项打勾
- [ ] 分工就位：建模（主）、编程、写作，各自开 Agent 窗口，**先读 AGENTS.md → handoff.md**

## 一、时间轴总览（每 6 小时一个 checkpoint）

| 时段 | 阶段 | 主线 | 三人分工 |
|---|---|---|---|
| 0--6h | 拆题 | 读懂题、写完拆题三件套 | 建模主导 problem-brief + question-map；写作提炼 submission-rule；编程看数据 |
| 6--12h | 数据地基 | 数据清洗留痕 + 数据侧写 | 编程主跑（data-log 每步留痕）；建模定假设与符号 |
| 12--24h | 问题一 | 数据关系/分布/相关性全做完 | 建模定打法；编程实现+出图；写作搭论文骨架 |
| 24--36h | 主模型（问题二/三的核心） | 联合模型 + 求解 | 建模+编程结对：先过六维审查再写代码 |
| 36--48h | 主模型收口 | 结果表可复算、场景区分 | 编程跑全量；建模核对数字口径；写作开始写前三章 |
| 48--60h | 检验与灵敏度 | 对比验证 + 参数扰动 | 编程跑灵敏度；建模定结论；写作写建模章节 |
| 60--68h | 论文成稿 | 全部章节 + 图表过 scientific-figure-making | 写作主写；建模/编程供给数字与图并逐字核对 |
| 68--71h | 摘要与自审 | 摘要最后反写 + paper-check + paper-review | 三人合读：外行可读测试、三方对账 |
| 71--72h | 提交 | checklist 逐项打勾、打包、提交 | 写作执行；另两人复核命名/格式/大小 |

## 二、四个硬节点（错过就砍内容，别硬撑）

1. **第 24h：问题一必须做完**——它的分布结论是后面所有问题的输入（官方权重：下游依赖的任务权重更高）
2. **第 48h：主模型代码冻结**——之后只跑灵敏度与结果整理，不再改模型结构
3. **第 60h：论文必须开写**——再好的结果写不完 = 0；此时没做完的问题降级为"方案 + 理由"
4. **第 71h：摘要完成 + paper-check 无硬伤**——摘要最后写，逐问报数值（见 `abstract.md`）

## 三、每个 checkpoint 的标准动作（所有窗口通用）

1. 读 `handoff.md` 确认交接
2. 干完本阶段主线，产出物落到对应目录（`01-problem/` → `02-data/` → …）
3. 结果跑完就按 `results.md` 命名规则追加一行（用 `new-result` 生成名字）
4. 更新 `handoff.md`（做到哪 + 下一步 + 踩过的坑）
5. 每 12h 跑一次 `paper-check`（提前清占位符与 AI 套话，别堆到最后）

## 四、三人协作规则

- **建模**：所有模型决策在 `model-review.md` 留痕；每个创新点写一张"创新卡"（`innovation.md` 第 3 步）；假设、符号、变量名一经定稿写入 `AGENTS.md` 速记，全员统一口径
- **编程**：每步数据操作写 `data-log.md`；代码在 `03-models/code/`（uv）；结果文件命名走 `new-result`；**先精确解后启发式**（能 LP/IP/MIP 别上 SA/GA）
- **写作**：第 12h 搭好 LaTeX 骨架（CUMCMThesis），每完成一问填一章；图表统一过 scientific-figure-making；写每章前翻对应 playbook（路由表见 SKILL.md）
- **三方对账**（第 70h 强制执行）：论文数字 = 结果文件数字 = 支撑材料数字，逐个数核对

## 五、紧急预案（按优先级砍）

| 危机 | 动作 |
|---|---|
| 时间不够 | 保中心耦合模型 + 核心验证 + 必要图表 + 题目对照；砍背景、装饰图、重复推导（官方权重：主模型占 70--75 分） |
| 代码结果不合理 | 先查：数据口径 → 单位 → 约束方向 → 随机种子 → 目标函数符号（`paper-review.md` 紧急处理） |
| LaTeX 编译失败 | 定位最近改的 `\input{}`、图表路径、未闭合环境、编码；退回上一个能编译的版本再增量恢复 |
| 页数超 30 | 先做 page-budget，全量明细迁附录/结果文件/支撑材料，正文留代表性结果 |
| 数据泄漏嫌疑 | 停手庆祝，先查：标准化是否用了全量均值、验证集是否参与训练、测试信息是否混入特征 |
| 队友掉线 | handoff.md 就是保险——任何窗口接手都能从"先读什么"三件套恢复 |

## 六、提交前最后 30 分钟（雷打不动）

1. `paper-check` 跑最后一遍 → 0 硬伤
2. `checklist.md` 逐项打勾（论文/结果文件/支撑材料三方一致）
3. 电子版第一页 = 摘要专用页；正文 ≤ 30 页；论文与支撑材料各 ≤ 20MB；全文无身份信息
4. AI 工具使用声明在参考文献之前；用了 AI 就附 `AI工具使用详情.pdf`
5. 打包前重命名按提交规则，提交后**留一人不睡**等确认回执
