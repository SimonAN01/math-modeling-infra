# AI 使用记录与提交

依据：[组委会 2026 年试行规定](https://www.mcm.edu.cn/html_cn/node/fef94648f2836ab6cc81586f4c38512b.html)。发布 2026-08-03，2026-09-01 起试行；本流程核对日期 2026-09-07。提交前再次核对当届通知。

## 日常记录

使用 AI 完成一项工作后立即更新 `06-submission/ai-usage.json`，不要到交卷时靠记忆补写。无论使用聊天、补全、代码助手或智能体，都按实际记录。赛前框架搭建不冒充赛中记录；如果其产物在竞赛中被采用，应由团队评估并如实披露。

- `status`：初始 `template`；团队按实际情况选择 `used` 或 `unused`。有 AI 记录不能选择 `unused`。
- `summary_purpose`：正文声明中的简要用途，必须与记录一致。
- `team_confirmed`：团队核对记录完整性后才能设为 `true`；AI 不得代替确认。
- `records`：每次工作追加记录，失败或未采纳也可保留。单条结构如下（示例字段说明，不是已发生记录）：

```json
{
  "id": "AI-001",
  "date": "实际日期",
  "tool": "工具名称",
  "model": "界面显示或其他可核实的版本/型号",
  "stage": "子问题及工作环节",
  "purpose": "具体目的",
  "prompt": "主要提示内容或典型交互摘录",
  "process": "输入背景、迭代过程和输出获取方式",
  "output": "项目相对路径及输出摘要",
  "language_only": false,
  "adoption": "采纳/部分采纳/弃用及范围",
  "modification": "人工修改内容，未修改则说明",
  "verification": "人工如何核验及结果，不能仅写已核验",
  "evidence": "复算、测试、原始来源或审查记录的相对路径/定位",
  "reviewer_role": "编程成员等匿名角色，不写姓名学校",
  "human_verified": false
}
```

核心模型、假设与结论仍由团队决定。AI 可以整理证据，不能替人把 `human_verified` 改为 `true`。纯语言润色可设 `language_only=true`，免于列示采纳、修改、核验详情；工具、用途、提示和过程仍须记录。涉及事实、公式、数据或结论的改变不能按纯润色处理。上述 JSON 是本仓库的工作约定，官方要求的是最终 PDF 的四类内容。

## 生成与检查

以下命令从项目根目录执行；框架在其他位置时替换脚本路径。

```powershell
# 赛前预览；只输出到 preview，不会覆盖正式声明
uv run math-modeling-infra/scripts/ai-disclosure.py build . --preview
# 记录完善、团队确认后生成正文声明与正式详情 PDF
uv run math-modeling-infra/scripts/ai-disclosure.py build .
powershell -File math-modeling-infra/scripts/build-paper.ps1 .
uv run math-modeling-infra/scripts/ai-disclosure.py check .
```

正式生成更新 `05-paper/ai-statement.tex`，使用 AI 时同时生成 `06-submission/support/AI工具使用详情.pdf`。`05-paper/main.tex` 已在参考文献前接入声明。自定义模板须接入此文件并用 `--paper 路径` 指定实际提交 PDF。不要把模板手册 `CUMCMThesis/example.tex` 当作参赛正文。

台账、声明、详情 PDF 的哈希保存在 `support/ai-disclosure-manifest.json`；台账变更后重新生成、重新编译论文。脚本验证编译 PDF 中的声明原文及顺序，无法判断人工核验是否真实完成。标题在正文中提前出现或特殊 PDF 提取顺序可能导致检查失败，应检查实际 PDF 并调整，不可把失败当作通过。

仅将正式 `AI工具使用详情.pdf` 放入最终支撑材料压缩包。`preview/`、台账中的私密交互和生成中间文件不应自动全部打包。正式 PDF 仍需检查匿名性、分页、字体与实际记录的一致性。未使用 AI 时仅生成对应声明，不要求详情 PDF。

## 用户 Word 样例对应的表格版（2026-09-07）

版式参考用户提供的 `AI 工具使用详情(1).docx`：工具清单、7个环节、5种提示方式、典型交互、6类采纳核验、5项团队主导确认。此文件是用户格式参考，不将其视为组委会强制模板。输出继续采用 LaTeX → PDF；纸张使用项目约定的 A4，标题字体使用可移植字体替代样例字体。

台账单条记录新增字段：

- `stage_group`：从下列7个环节中选一项；`stage` 继续填写具体子问或文件。
- `interaction_modes`：从下列提示方式中选择一个或多个，写为字符串列表。
- `response`：实际 AI 回复的核心内容，不能只给文件路径；`output` 保留输出位置。
- `output_category`：非纯语言润色记录从下列6类中选一项。

根级 `example_ids` 指定典型交互的记录 ID；留空默认选前3条。建议选2至3次；实际不足2次时如实列出，不凑数。全部非纯润色记录仍进入第四部分核验表，过程与输出位置另有补充页。

根级 `core_leadership` 已列出5项，每项含 `stage`、`team_led`、`contribution`。团队填写具体贡献并确认主导后才能设为 true；初始 null 表示未确认。结尾的本队确认文字只在正式校验通过后输出，预览明确标注尚未确认。

预览现输出到 `06-submission/preview/table-format/AI工具使用详情.pdf`，旧版 preview 根目录文件仅为上一轮预览。正式版路径仍为 `06-submission/support/AI工具使用详情.pdf`。

### 环节可选值

- 赛题理解与问题分析
- 模型假设与符号定义
- 模型建立与算法设计
- 模型求解与编程实现
- 结果分析与模型检验
- 论文撰写与文字润色
- 其他辅助环节（文献/数据/图表等）

### 提示方式可选值

- 网页对话框交互
- 代码编辑器内嵌AI
- 上传文件或数据对话
- AI智能体工作流（多步自动执行）
- 其他方式

### 输出类别可选值

- 建模思路与方法建议
- 公式推导与理论参考
- 代码编写与调试
- 结果分析与模型评价
- 论文核心论述（摘要/结论等）
- 其他内容

## 2026-09-09新增参考材料的对应

S19的用途词表仅供归类，不自动补入真实记录，也不为100—180字扩写官方声明。S20的工具、用途、提示过程、采纳修改核验四部分继续由现有台账生成。版本确实未显示时可如实说明“使用期间界面未显示具体版本”，不得猜测；没有查证的型号仍属待补信息。

每个实质性环节均应有记录，同工具同环节连续交互可合并但不能遗漏实际影响。主要提示与过程覆盖所有记录；典型对话只选代表样本。S20重复的A-02段落不重复建记录；编号沿用现有唯一ID规则即可。纯润色例外不涵盖改变公式、数值、事实或结论。

本轮赛前框架优化记录保存在项目交接与整合说明，不能自动声明为赛中用途或代填团队已核验。正式支撑清单只列需要提交的详情PDF，不把JSON私密交互和预览一同打包。
