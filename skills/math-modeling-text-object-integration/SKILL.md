# 数学建模论文润色：文字、图、三线表与公式的论证衔接

## 0. 任务与适用范围

你的任务不是在每张图、每个表和每条公式前后机械添加连接词，而是让它们成为论证的组成部分：读者能够理解为什么需要这个对象、应该观察或理解什么、它支持什么结论，以及下一步如何使用这些信息。

适用于预测、优化、评价、统计分析、机理建模、仿真、调度、决策等数学建模论文。既可用于写作新内容，也可用于润色已有正文。不将本技能默认绑定某一篇文章、某项比赛、某种模型或某套固定章节。

用户只要求通用技能时，提供规则、模板和示例，不自动检索旧稿或转为定向审稿。用户指定正文后，再按本技能检查该范围。

**核心口令：图前立问题，图后讲发现；表前定口径，表后作比较；式前说目的，式后释含义；段末交用途，下段接任务。**

这是一组信息职责，不是必须逐对象重复的固定句数。编辑质量按逻辑是否完整判断，不按新增文字多少判断。

## 1. 总原则：对象必须进入论证链

### 1.1 使用统一结构

> 任务或主张 → 对象引出 → 图／表／式 → 关键解释 → 当前结论或后续用途。

其中：

- 任务或主张：现在要解决、说明或验证什么？
- 对象引出：为什么用这个对象？读者重点看哪里？
- 关键解释：它具体显示了什么，或在数学上表达了什么？
- 当前结论或后续用途：它支持当前哪项判断，或成为下一步的什么输入、约束、依据？

对结果对象，可以先写结论句，再定位证据；对方法对象，通常先写建模目的，再给出结构或表达。不要强迫所有段落使用同一种顺序。

### 1.2 区分三种对象的主要职责

| 对象 | 主要职责 | 展示后应回答 |
|---|---|---|
| 图 | 展示结构、关系、分布、演化、空间差异或方法机制 | 最重要的关系或发现是什么？与当前问题有什么关系？ |
| 三线表 | 组织精确数值、比较口径、分类信息或符号参数 | 哪个比较最重要？差多少？什么条件下成立？ |
| 公式 | 定义量、表达假设、建立关系、给出目标或约束、完成推导 | 式子表达什么？符号是什么？条件是什么？如何进入后续模型？ |

公式给出模型表达，不自动证明模型有效；算法流程图展示计算结构，不自动证明算法性能；参数表说明设置，不自动证明设置最优。

### 1.3 保持优势主导，但让证据承担结论

围绕最有价值且有证据支持的发现组织图表解读。主动说明关键改善、结构特点或任务意义，不让读者从表格中自行猜测。

不得为了使衔接更有力量而新增未验证的优势。单条迭代曲线不能证明全局收敛；单个数据集结果不能证明跨场景泛化；参数量不能替代实际时延；相关图不能自动解释为因果关系；点估计变化不能自动写成统计显著或性能等效。

## 2. 执行前：建立对象职责卡

先扫描指定范围内全部图、表、公式及其相邻正文。以单个对象或功能紧密的对象组为单位，建立以下记录：

| 字段 | 填写内容 |
|---|---|
| 对象定位 | 编号、名称、所在小节；公式还记录标签或关键表达 |
| 当前任务 | 这一段正在解释或检验什么问题 |
| 对象类型 | 结构说明、结果证据、变量定义、目标函数、约束等 |
| 核心职责 | 用一句话说明对象存在的必要性 |
| 展示前信息 | 需要哪些目的、口径、变量或观察指引 |
| 展示后信息 | 需要解释哪些发现、数学含义或差异 |
| 后续接口 | 进入哪一步分析、求解或决策；没有则允许在此收束 |
| 信息状态 | 原文可支持、需查原图原表、需作者核验 |

对象职责可以用下面的句式检验：

> 该对象用于回答【问题】，读者应通过【结构／数据／表达】理解【关键结论或建模含义】。

写不出职责时，不立即补套话。先判断应当补充解释、移动位置、与其他对象合并，还是建议删除重复内容。关键验证和重要反证不能因结果不占优而删除。

## 3. 图片：展示前有观察任务，展示后有结论解释

### 3.1 图前应交代什么

图前根据实际需要说明当前分析目的、图中对象及必须知道的条件。定位语应使用准确编号，不依赖“下图”“上图”等易随排版失效的称呼。

基础模板：

> 为考察【因素／方法／条件】对【对象】的影响，在【统一条件】下比较【对象】，结果见图【编号】。

如果本段已经陈述目的，不重复“为进一步验证”。可以直接承接：

> 上述分解将【任务】划分为【环节】。各环节的信息流及依赖关系如图【编号】所示。

### 3.2 图后应交代什么

按照需要完成“观察事实—对应解释—任务意义”。结果段可先说最重要发现，再指明曲线、区域、节点或数值证据。

> 【核心发现】。图【编号】中，【可定位的曲线／区域／对比】显示【具体事实】。这为【当前主张】提供【适当强度的支持】，并用于【下一步任务】。

图后不是复述标题，不是逐一朗读图例，也不是用“效果较好”替代判断。没有机制证据时，只描述观察到的规律及其可支持的含义，不编写因果解释。

### 3.3 按图的类型调整解释

| 图类型 | 图前重点 | 图后重点 | 避免 |
|---|---|---|---|
| 总技术路线图 | 研究任务及总体组织方式 | 按章节需要解释主要接口；已有说明时可省略重复解读 | 把每个节点再抄一遍 |
| 单个问题的求解流程图 | 该问题的难点、拆分方式与求解逻辑 | 本题特有的依赖、反馈或输出去向 | 用一行引图语替代实质性问题分析 |
| 方法机制／结构图 | 为什么需要该方法，图中模块如何对应本题 | 输入输出、信息流、核心模块与后续数学表达的对应 | 无解释地贴通用教材示意图 |
| 性能对比图 | 统一比较条件和观察维度 | 关键差异、区间与任务意义 | 根据视觉差异断言显著性 |
| 参数／扰动图 | 参数含义、变化范围与其他控制条件 | 变化趋势、转折和已验证的适用区间 | 只写“曲线较平稳” |
| 迭代轨迹图 | 横纵轴和迭代设置；区别单次轨迹与重复试验 | 已观察到的变化、停止条件、是否需要另报可行性 | 将目标值平台等同于全局最优 |
| 分布／残差／空间图 | 样本、坐标、尺度及分组依据 | 集中区、偏差、异常区和下一步处理 | 从聚合图直接推断个体或因果结论 |

### 3.4 流程图和问题分析的特殊安排

若论文采用“问题N模型的建立与求解”章节，并将“问题N分析”设为首节，应先有实质分析文字，说明任务、关键困难、处理思路与环节依赖，再写：

> 问题一的求解流程图如图4.1所示。

随后放图。编号跟随所在章节或用户采用的模板，不固定为4.1。

实质分析通常需要一个完整段落或若干相连段落；具体篇幅由任务复杂度决定。用户已约定约半页分析时保留这一设置，不能压缩为一句引图语。

总技术路线图若明确采用极简呈现，可保留“本文整体技术路线图如图1.1所示。”后直接放图，不强行添加重复段落。

## 4. 三线表：表前定口径，表后提炼比较

### 4.1 先区分表的用途

不要把所有表都当成性能对比表。符号表、输入数据表、参数设置表、描述统计表、结果对比表和决策输出表的解读职责不同。

| 表类型 | 表前需要 | 表后需要 |
|---|---|---|
| 全局符号表 | 由小节标题和表头提供检索定位即可 | 已采用极简符号说明时，不强加解释 |
| 参数设置表 | 参数适用的模型、实验范围，必要的来源或确定方式 | 说明关键设置对后续步骤的作用；避免宣称未验证的最优性 |
| 描述统计表 | 样本范围、变量与单位 | 提炼影响建模的尺度、偏态、缺失或差异 |
| 性能对比表 | 对照对象、指标含义、方向与公平比较条件 | 主结论、关键差值、必要权衡和适用范围 |
| 消融结果表 | 去掉或替换什么、其余条件如何保持 | 结果支持到哪一级组件贡献，不超出控制设计 |
| 最终方案表 | 决策变量、单位、对象和约束背景 | 说明方案特点、主要资源配置与任务完成情况 |

### 4.2 表前不要只写“结果见表”

可以使用：

> 在相同【数据划分／预算／设备／约束】下，以【指标A】和【指标B】评价【对象】。表【编号】汇总【统计口径】下的比较结果。

不必把表头每一项都在正文解释。正文只说明理解比较所必需的信息；指标公式、单位和注释放在最合适的位置，避免三处重复。

### 4.3 表后按价值排序，不按单元格顺序朗读

表后优先解释与研究目标直接相关的主要发现。按需要指出一个至三个关键对比，而不是把所有行列再写一遍。

> 在【核心目标】上，【方案】取得【结果】。相较【基线】，【指标】变化【差值及正确单位】；与此同时，【另一指标】为【数值】。这说明【具体任务意义】。

存在权衡时，写明“条件—收益—代价—意义”；没有证据支持的权衡不补写。

### 4.4 数值、口径与版式检查

表头应能辨认指标和单位，必要时标明越大越优或越小越优。统计量的含义必须明确，例如均值、标准差、中位数、分位数或区间，不能只写一个未解释的“±”。

注意“百分点”与“相对百分比”的区别；计算改善率时说明基准和指标方向。不同数据、预算或样本口径下的数值，不直接计算为公平的改进幅度。

通常采用顶线、表头分隔线与底线，并避免竖线和不必要的网格。分组辅助线、表题位置和跨页形式遵循具体模板。三线表是一种排版形式，论证质量来自表的组织和正文解释，而非三条横线本身。

## 5. 公式：先说明数学任务，再解释模型含义

### 5.1 公式不是独立插入的装饰

推荐结构：

> 建模目的／推导依据 → 公式 → 新符号与条件 → 数学或任务含义 → 后续用途。

公式是句子和论证的一部分。公式后的标点随整句语法和模板统一，不将显示公式自动当成一个已经解释完整的段落。

### 5.2 根据公式类型选用准确的引导动词

| 公式类型 | 展示前可用 | 展示后应解释 |
|---|---|---|
| 定义式 | “定义”“记为”“采用……度量” | 符号、量纲、取值方向与使用目的 |
| 建模关系 | “在……假设下，表示为”“采用……刻画” | 假设、近似性质与变量关系 |
| 目标函数 | “以……为目标，建立” | 优化变量、各项作用、权重及尺度 |
| 约束 | “为满足……，要求” | 可行性要求及每类约束的现实含义 |
| 推导式 | “代入”“展开”“消去”“结合……可得” | 关键变形依据，新增条件与得到的性质 |
| 更新式 | “第k次迭代按……更新” | 状态、步长、依赖信息和停止条件的位置 |
| 指标式 | “为评价……，采用” | 指标方向、统计范围与结果解读口径 |

不要把人为设定写成“由此证明”；不要将一个建模选择伪装成逻辑上唯一的结果。

### 5.3 符号应在首次有效使用附近可理解

给出理解公式所需的对象、索引、变量角色及单位。新出现的局部变量在紧邻公式的文字中解释；全局符号已在符号表或前文定义且此处无新含义时，不重复长篇定义。

变量说明不是公式解释的全部。“其中x为……，y为……”之后，通常还需要说明这个式子如何度量、约束或连接实际问题。

检查标量、向量、矩阵、集合的区分，以及时间下标、样本下标、幂和迭代次数是否混用。目标函数的加权项若量纲不同，应有尺度处理或有明确单位的权重；不得仅在润色时宣称已经完成处理。

### 5.4 连续公式应有层级和推导路标

不要将目标函数、约束、矩阵形式、求解条件和迭代更新无解释地堆在一起。按功能组织公式组，并在关键转换处说明：

> 为将【要求】纳入模型，增加……
>
> 将式【A】代入式【B】，消去【变量】，得到……
>
> 为便于【计算方式】，将上述关系改写为……
>
> 上述表达给出了【对象】，但尚需满足【现实要求】，因此设置……

不是每个代数等号之间都加一句话。简单展开可用一个对齐公式组呈现，在组前交代目标、组后解释关键结果。

### 5.5 公式展示后的解释不能越级

目标函数说明优化偏好，不证明算法找到最优解；约束说明模型要求，不证明计算结果已满足约束；参数更新式说明迭代规则，不证明收敛；误差指标定义不证明结果足够准确。

需要相应的证明、可行性核验、计算报告或实验结果，才能进一步提出上述主张。

### 5.6 编号与回指

遵循模板，对会被回引的关键定义、目标、约束和重要推导结果编号。并非所有短小辅助表达都必须单独编号。

文字应引用准确的式号；连续公式的分组方式以便于后文定位为准。使用LaTeX时优先用标签和交叉引用维护编号，避免手写数字与排版不同步。

## 6. 图题、表题、图注、表注与正文分工

| 位置 | 主要职责 |
|---|---|
| 图题／表题 | 准确命名展示对象、比较维度或适用条件 |
| 图注／表注 | 补充阅读必需的条件、单位、缩写、统计量、颜色线型、误差线、来源及标记含义 |
| 正文 | 提出问题，选择关键证据，解释其与研究目标的联系 |

让图表具备局部可读性，但不要把整个实验设置复制进图注。正文也不能被一句“具体见图注”取代。长图注并不能自动补全正文的论证缺口。

## 7. 跨对象、跨段和跨问题的承接

### 7.1 承接应传递具体对象，而不是只传递语气

弱承接：

> 综上，结果较好，为后续研究奠定基础。

强承接：

> 上述估计得到的【参数／分布／需求量】作为下一节【目标函数／约束／仿真】的输入，用于确定【具体输出】。

若下一节是独立任务，直接说明视角转移，不强造因果或输入关系。

### 7.2 常见接口模板

| 接口 | 承接模板 |
|---|---|
| 分析文字→流程图 | “据此，将求解组织为【阶段】；阶段间的依赖关系如图【编号】所示。” |
| 流程图→公式 | “图【编号】给出了总体流程，以下对其中的【关键环节】进行数学表达。” |
| 公式→结果表 | “依据式【编号】在【条件】下求解，所得【决策量／评价值】汇总于表【编号】。” |
| 结果表→诊断图 | “表【编号】给出总体比较；为识别【差异的分布／来源】，图【编号】进一步展示【细节】。” |
| 图表→决策 | “在【约束】下，【发现】支持选择【方案／参数范围】，其依据为【具体比较】。” |
| 问题一→问题二 | “问题一得到的【输出】进入问题二的【模型位置】，用于【目标】。” |

接口必须与真实模型结构一致。没有残差图时不能宣称已展示误差来源，没有后续使用时不能假称“为下一问提供输入”。

### 7.3 图和表同时保留时需要互补

图可展示趋势、分布或结构，表可提供精确数值与完整比较。二者使用同一数据并不一定重复，关键是是否帮助读者回答不同问题。

若图表与正文三次重复完全相同的信息，应合并、精简或调整职责。

## 8. 高频问题及处理方式

| 问题 | 识别标志 | 处理 |
|---|---|---|
| 无引出对象 | 小节标题后直接放图、表或公式 | 补充任务、必要背景和观察／数学目的 |
| 只有定位语 | “如图所示”“结果见表”“如下式”后没有说明 | 把缺少的问题、口径或意义补全 |
| 展示后跳题 | 图表公式之后直接进入下一小节 | 补充当前发现／含义，或明确后续接口 |
| 正文朗读对象 | 逐个复述节点、行列和所有数值 | 保留关键对比，其他信息留在对象中 |
| 只有符号词典 | “其中……”之后没有模型解释 | 说明式子的现实作用和使用位置 |
| 公式堆叠 | 连续多式但关系不明 | 按定义、目标、约束、求解分组，补转换依据 |
| 标题式解释 | “图表展示了实验结果” | 换成具体发现和可支持的结论 |
| 万能收尾 | “验证了有效性”“为后文奠定基础” | 写清验证何种主张、向后文传递什么 |
| 证据过载 | 每句话都称“显著”“鲁棒”“最优” | 按实际证据校准结论强度 |
| 机械模板 | 每个对象都使用同样四句话 | 合并共享引入、变化语序、删除重复信息 |
| 引用失配 | 编号、指标、图例、变量与正文不一致 | 联合校验正文、对象、标题和引用 |

## 9. 合理例外：不要把衔接规则变成废话生产器

完整解释可以分布在对象周围，而不必紧贴对象两侧各写一段。排版浮动导致图表与引用不在同一位置时，按逻辑首次引用和可读距离检查，不承诺绝对相邻。

一组共享任务和口径的图表，可以统一引出、统一解读；关键公式组同理。

总技术路线图、全局符号表、查阅型参数表、附录明细等，若已有充分定位或用户明确采用极简格式，不强行套用主结果的解读模式。局部符号的新含义仍须解释，必要参数来源仍须交代。

当前论证已经结束时，允许以具体结论收束，不必每段都追加“接下来”。已由前文说明的模型动机、实验设置和指标定义，不重复堆写。

## 10. 标准执行流程

### 第一步：定位

只处理用户指定范围。读取图表公式及必要的前后文；不能凭标题猜测对象内容。原图、数值或公式无法确认时，将缺口记录为核验事项。

### 第二步：判定职责

建立对象职责卡，明确是定义、机制、比较、验证、结果汇总还是检索信息。先确定对象在论证中的位置，再决定需要补什么文字。

### 第三步：补足局部闭环

补充最必要的引出和解释，优先重写现有句子而非机械增文。保留数字、公式、变量、引用、方法归属、条件和结论方向。

### 第四步：连接前后任务

检查模型输入输出、变量、目标、约束、求解、验证和决策之间是否能够沿正文追踪。涉及不同问题时，区分真实依赖和并列关系。

### 第五步：校验一致性

核对图表标题、轴标签、图例、表头、单位、统计量、式号、符号、上下标与正文表述。数字变化可复算时复算；无法复算时不擅自确认。

### 第六步：压缩重复并保护例外

删除无信息套话，合并共享设置，避免正文重复图注、表头和全局符号表。保留用户明确指定的极简章节安排。

## 11. 输出合同

用户提供具体正文后，默认交付：

**A. 衔接诊断表**

| 位置／对象 | 原文问题 | 缺少的职责 | 可直接替换的图表式前文 | 可直接替换的图表式后文 | 需核验信息 |
|---|---|---|---|---|---|

只处理确有问题的对象，避免为了表格完整而重复列出全部正常内容。

**B. 连贯替换稿**

给出包括必要上下文、对象占位位置和引用的完整段落。不是只给出若干互不连贯的句子。

**C. 必要的结构调整**

指出需要前移、后移、合并或移入附录的对象，说明论证理由。改动复杂公式或实验设计时先标注建议，不以“润色”名义静默修改技术内容。

**D. 作者核验事项**

将缺数据、缺定义、无法核实的比较和证据不足的解释单独列出。不把待办、虚构数值或编辑批评混入可提交正文。

用户要求只返回成稿时，保持成稿整洁；不可确认的信息保留安全、明确的表述，并将会影响正确性的缺口作简短说明。

## 12. 交付前验收

- 每个关键对象能说明为什么出现在这里；标题下不无缘无故堆放对象。
- 每个结果对象有具体发现，每个关键公式有数学含义；不止“如图所示”和“其中”。
- 读者知道主要比较口径、指标方向和必要条件。
- 关键符号首次使用可理解，变量角色和量纲一致。
- 图表公式与正文编号、名称、范围和数值相符。
- 图注、表注、正文各司其职，不三次复制同一内容。
- 对象与前后模型环节能够对应，或在当前问题上清楚收束。
- 未新增未验证的显著性、因果、最优性、鲁棒性或泛化主张。
- 极简符号表和总体路线图等约定没有被机械破坏。
- 润色后的篇幅增长来自必要信息，而不是连接词和模板套话。
