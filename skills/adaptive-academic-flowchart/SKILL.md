# 学术流程图绘制：内容约束明确，结构与配色自适应

## 0. 核心任务

把真实的研究或求解逻辑整理成可读的流程图，而不是把研究内容塞进预设的六阶段模板。

**先判定内容关系，再选择布局与分组，最后设置配色。**

本技能中的示例不是必填节点，建议数量不是配额，候选配色不是固定语义表。

用户只要求通用技能或修订调用提示词时，输出可复用规则，不根据历史论文构造具体流程。用户给出实际内容后，只依据指定内容设计。输入中的“……”表示尚无具体题目，不据此生成某一研究的完整流程。

## 1. 区分三层要求

### 1.1 内容硬约束

1. 问题X求解流程图的矩形节点不出现公式本体、展开式、目标函数或数学推导。
2. 节点不出现已经求得的具体答案。既包括数值、排名、路径，也包括具体分类判定等非数值答案。
3. 节点可以写步骤名、任务名、方法名、模块名、输入类别、输出类别。输出类别不等于实际答案。
4. 节点、分支、检验及反馈必须来自真实方法。不得为了图形完整而补造步骤。
5. 箭头表示真实的执行、数据或条件依赖，不能把章节先后直接当作依赖关系。
6. 不写研发尝试史，不用“先进”“优秀”“证明有效”等空泛评价代替任务。
7. 不将未证明的求解结果称为“最优解”。一般使用“求解方案”“配置方案”等准确名称。

公式和实际答案回到正文、公式块、结果图或结果表中，不通过把内容移到箭头或注释上绕开上述约定。

### 1.2 本项目的基础视觉约定

- 小矩形承载一般任务、模块和输入输出类别。
- 矩形使用浅色填充，文字采用黑色粗体。
- 流程连接使用实线、实心箭头，优先正交走线。
- 有真实归属关系时，使用灰色大虚线框分组。
- 保持白色背景、对齐关系和均匀留白。

真实条件判断可以采用明确标注的判断节点；普通任务继续使用矩形。不要为了全图只有矩形而掩盖分支条件。

### 1.3 需要随内容决定的部分

以下内容不得写死：阶段名称与数量、是否存在数据处理、是否存在训练或检验、是否需要单列输出、节点数量、主路径方向、并行分支、反馈回路、虚线框数量，以及颜色对应的分类方式。

**保留稳定的视觉语言，不强迫不同研究具有相同的流程结构。**

## 2. 先确定图的职责与抽象层级

先用一句话说明：

> 本图展示【任务】中【主要对象】经由【关键处理关系】形成【输出类别或任务状态】的逻辑，重点突出【关键依赖、并行组织或反馈】。

对于不同图种，调整展示层级：

- 总技术路线：研究模块、问题关系、共享信息及跨模块接口，不展开全部实现细节。
- 问题求解流程：本题的关键步骤及依赖，不把公式和结果搬进节点。
- 算法流程：必要的初始化、更新、判断与终止，仅在算法实际存在这些环节时呈现。

不要把同一条泛化链复制到所有图中。总图与逐问图的区别应来自抽象层级，而不只是标题不同。

## 3. 从真实关系选择结构

### 3.1 建立最小内容清单

在内部识别：

- 需要展示的任务或对象是什么；
- 哪些是主路径，哪些是侧向输入；
- 哪些步骤并行，在哪里汇合；
- 是否存在真实条件分支或反馈；
- 哪些节点共享阶段、子任务或模块归属。

输入、处理、建模、求解、检验、输出可以作为检查视角，但不是每图必须出现的六个节点或六个阶段。某环节不存在就不添加；由前文交代且在图中不重要时，可以省略；存在多次求解或多个模型时，可以按真实关系展开。

### 3.2 选择布局

| 内容关系 | 可选布局 | 必须保留的含义 |
|---|---|---|
| 连续处理 | 纵向或横向单主链 | 顺序明确，方向稳定 |
| 多路处理后融合 | 并行分支—汇合 | 分支不是前后串行 |
| 不同条件走不同路径 | 判断—分支 | 条件和出口对应 |
| 反复更新直至终止 | 主链加侧面回路 | 返回位置、继续条件和退出条件清楚 |
| 多个子模型协同 | 模块化或混合布局 | 模块接口和信息传递真实 |
| 主过程依赖多类外部信息 | 主链加侧向输入 | 输入接入真正使用它的节点 |

布局由关系决定，不为了对称添加节点，不为了顺眼删除关键分支。

### 3.3 分组不预设三阶段

组框可表示求解阶段、并行方法、子任务、数据来源或模型模块，但同一级分组应采用可理解的分类依据。

没有自然分组的短流程不必嵌套大框。存在自然分组时，根据节点和走线范围设置框，不先规定三个框再填内容。

分组标题使用准确短语，例如“特征构建”“候选方案搜索”“结果融合”。不要所有图都固定使用“信息准备—模型建立与求解—结果分析与输出”。

## 4. 节点命名：不放公式与答案，但保留专业辨识度

### 4.1 允许的内容

- 操作或任务：缺失值处理、构建约束、估计参数、提取特征。
- 具体方法或模块：模型的正式名称、实际使用的算法名称。
- 输入类别：观测数据、边界条件、候选方案、上一问预测结果。
- 输出类别：预测序列、配置方案、诊断结果、评价排序。

“4—10个汉字、优先一行”是紧凑表达的建议，不是截断术语的硬规定。方法专名可以保留必要长度与数字；方法名称中出现数字不等于节点含有答案。

### 4.2 禁止内容及替换

| 不合适的节点 | 可以改为 |
|---|---|
| 写出完整目标函数 | 构建目标函数／构建优化模型 |
| 解得某参数为具体数值 | 参数估计／参数结果 |
| 最终路径为某条具体线路 | 路径求解／输出路径方案 |
| 预测需求为具体数值 | 生成需求预测／需求预测结果 |
| 判定为某个具体故障类别 | 故障判别／输出诊断结果 |
| 本方法效果显著优于基线 | 对照评价，仅在确有此步骤时 |

### 4.3 不要过度抽象

不能为了避免公式，把所有题目都写成“数据处理—建立模型—模型求解—结果输出”。优先保留实际对象与方法，例如把确实实施的“包络解调”“谱峰匹配”保留为节点，而不是一律改成“特征处理”。

一框一项可识别任务。复杂模块可以在本图保持概括，再在另一张算法图展开，避免一张图混用多个细节层级。

## 5. 配色自适应：先确定颜色的职责

### 5.1 不采用固定角色—颜色表

不要求输入永远浅蓝、建模永远浅绿、求解永远浅橙、检验永远浅紫。是否存在这些类别以及是否值得用颜色区分，都应由当前图决定。

颜色可以帮助区分阶段、模块、分支或功能；如果图本身没有需要突出区分的分类，就使用统一浅色，不为用齐颜色增加类别。

### 5.2 可选择的配色策略

| 当前图的重点 | 可采用的策略 | 使用方式 |
|---|---|---|
| 顺序本身已经清晰 | 单色或同色系 | 普通节点统一浅色，分组靠位置和标题 |
| 明确分为若干阶段 | 按阶段配色 | 同阶段节点共享浅色，阶段含义由标题说明 |
| 多条方法或子任务并行 | 按分支或模块配色 | 每条支路或模块形成视觉一致性，汇合节点使用中性色或明确的共享色 |
| 输入、操作、输出等角色是阅读重点 | 按功能配色 | 为当前实际角色选择颜色，不添加缺失的角色 |
| 需要突出一条关键路径 | 中性底色加少量强调 | 主要用于重要步骤或接口，不把较弱色解释为较差方法 |

选择一种主要编码方式。不要在没有说明时，让一部分颜色表示阶段，另一部分颜色表示性能好坏。

### 5.3 具体颜色只是候选值

可选浅色示例：浅蓝 `#E8F1FB`、浅绿 `#E8F3EC`、浅橙 `#FFF1DF`、浅紫 `#F0EBF7`、浅灰 `#F3F4F6`。

这些颜色没有预绑定的任务含义。可只用其中一种，也可选择适合当前分类的若干颜色。避免高饱和填充遮弱黑字；避免用渐变、阴影或大量彩色边框增加装饰。

### 5.4 一致性的范围

同一张图内，已赋予颜色的含义保持一致；同一论文中，同类图和相同分类尽量沿用同一映射。

当不同图的分类确实不同时，可以更换颜色组织方式，但应统一整体浅色风格、黑粗体、线条和密度，用组名、节点名称或必要图注说明当前分类。不要让读者只能靠颜色理解结构。

**统一的是表达习惯，不是强制所有图共有“输入／建模／求解／检验”四类。**

## 6. 箭头、分组与版面

### 6.1 连接关系

主链优先维持一个阅读方向。正交连接不穿节点、文字或组标题，跨组走线留出通道。

箭头清单用“起点—终点—含义”记录。普通执行顺序可不逐条标注；跨模型传递标明对象类别；条件分支标明条件；反馈标明返回条件与目标位置。

节点中不放公式的约定不等于不能表达逻辑条件。可用“达到停止条件？”等语言表达，并在正文给出精确定义，不把详细不等式塞到连接标签中。

### 6.2 分组框

灰色虚线表示归属，不表示流程顺序；实线实心箭头表示流程或传递，二者语义不要混淆。

组标题预留位置，节点不贴框线，连接入口避开标题。框的大小由实际内容决定。

### 6.3 视觉检查

同一层级尺寸与字号协调，不强求所有不同角色节点完全同尺寸。节点过长时优先精简表达、合理换行或拆分模块，而不是缩小全图字体。

按论文实际插入宽度检查文字、箭头标签及分组标题。图在编辑画布上放大后清楚，不代表放入论文后可读。

## 7. draw.io 实施与文件交付

需要实际绘图时，依次完成：内容清单、连接关系、布局草排、节点母版、分组框、连接布线、配色统一、最终尺寸检查。

支持生成文件时，优先保留原生可编辑 `.drawio`。节点、文字、连接器和组框应能独立编辑，不将整张栅格截图作为所谓源图。

具体菜单、样式键和导出选项以已核实的当前工具说明为准；不要编造软件功能。只完成结构或XML检查时，不声称已经完成原生渲染验收。

用户当前只要求技能或提示词时，不默认生成具体图，也不调用图像生成来替代规则说明。

## 8. 执行流程

1. 识别请求：通用技能修订，还是依据实际内容绘图。
2. 提取真实任务关系，先确定图种、范围和抽象层级。
3. 起草节点并检查公式、具体答案、虚构步骤与无依据评价。
4. 判定线性、并行、条件、反馈或混合结构，选择布局。
5. 识别自然分组；没有必要时，不添加分组层级。
6. 决定颜色是否承担语义；选择单色、阶段、模块、功能或强调策略。
7. 统一黑粗体、浅填充、实线实心箭头和有意义的虚线分组。
8. 核验真实连接、正文对应、标签一致性及最终尺寸可读性。

## 9. 输出合同

设计具体图时输出：

A. 结构选择与分组依据。自然存在阶段时给阶段划分；没有阶段关系时给模块或分支划分，不勉强命名为阶段。

B. 节点文字表。给出节点名称与归属，必要时注明对应正文位置。

C. 箭头关系。明确主路径、侧向输入、并行汇合和实际存在的反馈。

D. 配色与布局建议。说明当前图选用哪一种颜色组织方式，以及为什么适合；不复制固定角色配色表。

E. 实际可交付的文件与核验状态。仅在生成或检查确实完成时报告，不宣称未执行的渲染结果。

材料不足时说明哪些关系不能确定。用户尚未给具体问题时，输出可复用模板或标明假设的结构示例，不冒充该题已经成立的技术路线。

## 10. 验收清单

- 矩形里没有公式、已求得的数值答案或具体分类结论。
- 输出节点描述的是输出类别，而不是具体答案。
- 节点保留必要的方法特色，没有全部退化为泛化词。
- 没有为了凑六阶段而新增处理、训练、检验或输出步骤。
- 没有为了四种颜色而新增四类节点。
- 阶段、模块和分支关系与实际内容一致。
- 箭头有真实依据，反馈和汇合没有伪造。
- 配色有一种清楚的主要组织方式，也可以不承担分类语义。
- 同图映射一致；不同分类的图可以调整，整体风格仍协调。
- 分组框有真实归属意义，不强制三组或多层嵌套。
- 黑字粗体、浅色填充和清楚走线在最终尺寸下可读。
- 图中术语与正文一致，未新增无证据的“最优”“显著”等主张。

## 11. 调用

复制 `prompt.txt` 作为日常调用提示词。

需要比较不同结构时，读取 `references/adaptive-examples.md`。示例只示意结构，不是任何具体题目的默认方案。

**最终标准：研究逻辑决定图的结构，图的结构决定视觉组织；固定的是内容底线与基础风格，不是节点类别、阶段数量或配色映射。**
