# 连边协议：语义、接口、几何三层分离

## 1. 逻辑层：为什么存在这条边

连接表先于布局。每条边都有id、两端语义节点、命名接口、kind、meaning、evidence、status；分支有condition。正式图只含 confirmed。资料不能支持的关系，不用虚线猜测。

对于同一输入分发到两个分支，应有两条分别说明用途的关系；对于两个支路互不交换信息，不能因为并排而加互连。选择、串接、拼接、求和、融合是不同操作，不可统一画成圆点。

方向是信息或执行的方向，不是视觉上从左到右。归属用组框，相关不等于因果。控制是否执行与传递什么数据可以是不同边，但只有材料明确需要区分时才画两根，避免人为加密。

示意图允许抽象中间步骤，但需记录 `abstraction` 与省略范围，不能把跨过中间操作的线说成直接调用或直接因果。关系依旧需要依据。

## 2. 接口层：连接哪个输入／输出

节点可声明逻辑端口：

```json
{"id":"evaluate","role":"process","ports":{
  "candidate_in":{"direction":"in","channel":"candidate"},
  "score_out":{"direction":"out","channel":"score"}
}}
```

channel 是本任务自定义、已核实的数据或控制类别，不是软件自动推理的类型系统。复杂关系只在科学含义成立时设为 compatible；禁止随意把所有channel写成any来躲过检查。

场景只把相同命名端口映射到坐标：

```json
{"id":"evaluate","ports":{
  "candidate_in":{"x":0,"y":0.5},
  "score_out":{"x":1,"y":0.5}
}}
```

相邻相同节点也不能交换id。图上缩写相同的两个模块，仍用独立身份和正确接口。

## 3. 几何层：怎样接到这个接口

- `source/target` 是真实模块cell ID，不是连接点坐标。
- `exitX/exitY` 与 `entryX/entryY` 是相对位置；明确写 `Dx/Dy=0` 和 perimeter，避免固定点被遗失。
- 矩形可在同侧按0.25、0.5、0.75等分配多个不同入口，间隔仍要满足字号与线宽需要。
- 非矩形用匹配perimeter；优先边界明确的上／下／左／右中点。复杂内部端口要经渲染确认；不能猜矩形包络点就是可见边界。
- 可以为shape设置 `points=[[0,0.5],[1,0.5]];` 便于编辑器人工吸附，但这只是候选连接点，不替代edge的实际端点绑定。
- 需要精确内部接口时可构建独立原生接口节点，并将其映射回语义节点；本包普通构建器采用模块上的命名固定点，不自动支持所有自定义端口图元。

官方文档区分 fixed 与 floating connector：fixed移动模块后仍停在那个固定点，floating可能沿边界漂移；是否显示连接点也不等于是否绑定了对象。查看 `technical-sources.md`。

## 4. 布线约定

主干尽量方向一致；并行端口与对应支路对齐；反馈绕真实循环体，不绕整个页面。多条跨区线按目的地次序排列。显式waypoint坐标属于edge的parent坐标系，不一定是全图坐标。

水平出端口先水平离开，垂直出端口先垂直离开；进入亦然。先考虑模块位置与端口，再考虑拐点数量。固定端点保证吸附，不保证自动路由正确或美观。

条件标签跟随对应边；默认在源点附近，长条件在正文或图注解释，图上用准确的短条件。不能让“是／否”漂到两条线正中。

交叉无交互：不加合流圆点。实际共享数据的总线：需显式模型和分发关系；不能为了少画几条线变成不明合流。绘制专用junction时，先在关系表登记其身份、类型和依据。

## 5. 冻结与比对

生成后比对三者：topology → scene → XML。检查边集合完全匹配；source/target没有交换；端口与channel匹配；分支条件标签一致；没有多余双箭头；正确的固定点值保留。

修改版式后再比对冻结前后的topology；仅几何变化不应改变它。发现关系表自身有错时先按证据修订并记录，不要把关系表当不可纠正的真理。

自动检查只能发现声明间矛盾，不能发现所有共同错误。模型或人工必须独立把箭头逐条读成一句话，并对照原材料："A将什么送到B？何时？证据在哪？"。
