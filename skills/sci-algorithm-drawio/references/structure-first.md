# 先确定整体结构，不在 XML 中边摆边想

## 必交的结构摘要

用十余行或一张表交代图种、核心职责、主干顺序、阶段归属、并行身份、真实分叉与汇合、反馈目标、目标宽度和预计字号。它是可检查的设计结果，不是要求输出私人思考过程。

## 先完成参考研究

进入下面的结构设计前，按 reference-first.md 联网找与机制匹配的原图，实际看图与读说明。输出 references.json / reference-review.md。下述分区与布局不得由模型凭算法名随意构造；参考也不能覆盖当前材料的真实关系。

## 从关系到布局

1. 抽取计算对象与操作；把数据流和控制流区别开。
2. 每个箭头找依据；对缺口标 unresolved，而不是凭通用算法经验补齐。
3. 单列反馈关系，识别循环体与终止出口。前向依赖用于分层，反馈保留。
4. 根据“协作职责”分区，优先将强交互留在同一区。框是归属，不是流程边。
5. 判断图种。整体总览不需展开所有算子；机制图重点必须有对象或内部关系。
6. 复杂图比较两个布局候选：行列关系是否清楚、回路是否绕远、是否产生空栏、字号是否达标。输出候选简述与选择，不写长篇评审。
7. 先画逻辑骨架的文字表，不先造大空容器。确定阅读方向、端口职责与通道。
8. 测量标签和对象；自下而上算模块、子组、阶段；填入几何计划。
9. 检查跨区边数量和接口顺序。能通过交换相邻支路减少交叉时优先换位置，但节点身份和真实关系不变。
10. 冻结拓扑；生成场景；版式修改做关系差异检查。

## 四个常见结构错误

- **并行被串联**：为了形成从左到右的漂亮链，把互不依赖的步骤接起来。改为同行列对齐的分支，是否连接由材料决定。
- **三栏各占三分之一**：输入一个框，核心十二个框，输出两个框，却强制等宽。按内容所需宽度分配，简单区域收窄。
- **先画大循环再寻找目标**：回箭头看似闭合，却返回了初始化。应明确被更新的状态，返回真实入口。
- **汇入即融合**：多条线碰到一个点，被误读为拼接或相加。没有真实合流算子时，不用合流圆点或共线。

## 没有复杂信息时不要假装复杂

紧凑的六节点流程可以很好；高密度不要求塞满画布。减少画布面积和多余边距，保留清楚的逻辑即可。内容本身不足以支撑多阶段，就不设置多阶段大框。
