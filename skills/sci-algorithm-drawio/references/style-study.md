# 对用户 Draw.io 参考的实际风格分析

## 1. 检查对象和观察边界

原文件：`user-reference.drawio`。解析结果为 **1 个 diagram 页、134 个 mxCell（含两个结构 cell）、103 个 vertex、29 个 edge、9 个 image 节点**。一个页中有四组主要图：文本特征提取、语音特征提取、视觉特征提取、多模态缺失鲁棒情感预测网络。上方还散放了若干备选模块。

这意味着用户说“里面好几张图”是指一个大画布上摆了多张图，不应未经检查就写成“多页模板”。几组完整图值得学习；画布留白和散件不是必须复现的版式。

随包裁图来自原始坐标与嵌入素材的近似渲染，不是 Draw.io 官方导出；细节路由和字体回退可能有差异。以下构图判断同时参照了 XML 中的对象、样式和坐标。

## 2. 文本特征提取图

参见 `source-crops/text.png`。

结构是一个横向总框，上部浅灰标题带，下部是三个阶段：嵌入预处理、编码块、特征序列。中间栏比左右栏宽，内部呈现并列的编码器结构，而不是只有“编码器”三个字。右侧把输出画成竖直条带、括号与省略表示，而不是写一个笼统的“输出”。阶段之间使用较显眼的空心箭头。

值得学的是**三种不同的阶段表达**：左边用短处理链，中间用内部结构，右边用对象表示。它们受统一的外框、标题和基线约束，所以视觉并不散乱。

迁移到数学建模时，保留“来源／预处理—核心操作—结构化结果”的语法；不要复制 BERT、层数、变量或具体维数。若内部结构是主要解释对象，应在 Draw.io 中重建其子模块与连接，而非继续保存为一块带文字的截图。

## 3. 语音特征提取图

参见 `source-crops/audio.png`。

左栏通过两组波形局部图与短标签区分输入组成；中栏用虚线分组容纳时间窗与几类属性；右栏继续用竖直条带表示序列。内部小方框并非随机装饰，它们表示不同属性项。左右主阶段空心箭头与内部细箭头分工不同。

此图表明：**框比较多、文字不算少，也可以清楚；关键在于同组聚集、阶段分隔、对象表示重复一致。** 不该把它压缩成三个含糊大框，也不该把每个小框都换成装饰图标。

可迁移到传感器、时间序列、评价指标、特征工程或信号处理图：输入的粒度、局部处理对象和输出表示必须明确。但示意波形不等于实测曲线，不能伪装成结果。

## 4. 视觉特征提取图

参见 `source-crops/vision.png`。

左栏是带标识信息的原始视频帧，中栏展示同一场景上的局部标记，右栏是特征序列。三栏的数据身份保持关联，所以读者能够理解从原始对象到定位或提取，再到结构化表示的转换。

最值得学的不是人物照片，而是**同一对象的连续性**。迁移时可用同一张路线、同一组节点、同一块栅格或同一个工件，在前后阶段展示相应操作。

真实照片可以保留为局部素材；检测边界、作用位置、标签和算法关系应独立可编辑。不得拿参考中的人物、标记或结果冒充新论文数据。

## 5. 多模态预测网络图

参见 `source-crops/network.png`。

整体采用更宽的分栏框架：预处理输入、单模态支路、跨模态与时序融合、双任务输出。内部还有并行行、虚线子组、多个小处理框和合并／分出关系。这个图区本身确实以框和短文本为主；不能为了迎合“机制图必须少框”而否认它的主要表达方式。

它提供了另一类参考：**当任务是交代架构时，模块与连接本身就是有价值的机制信息。** 不要求每个归一化模块都再配插图；真正需要展开的是当前论文的重点关系。

值得迁移的是行列对齐、阶段—子组—模块的层级以及真实支路；不值得迁移的是全部公式、极宽比例、重复冗长算子标签或容易混淆的交叉线。正式图须按单图插入尺寸重新排版，不能把整个工作画布一起缩进论文。

## 6. 可验证的样式信息

源文件直接写出的属性包括：

- 常见矩形 `rounded=0`，有需要时局部用圆角虚线边界。
- 多个边框使用 `strokeWidth=1`，部分内部框／连接使用 `2`。
- 四个浅灰标题区域显式使用 `fillColor=#E6E6E6`。
- 显式字号以 `21`、`19`、`18`、`23` 等为主；它们是原文件坐标尺度中的样式值，不是最终印刷字号。
- 空心阶段箭头使用独立箭头形状；其他关系包含原生 edge。
- 淡蓝、淡绿和一些编码器内部配色来自嵌入图片，不能只数原生 `fillColor` 就宣称整图没有颜色。

视觉上正式衬线标题较突出；源文件只对部分原生对象指定 `Times New Roman`，其余字体和中文回退需依实际渲染环境判断。不要声称已确认整图统一采用某一种中文字体。

## 7. 可编辑性：学习风格，同时改进实现

源文件的非结构对象均以顶层 `parent=1` 为父级，因此很多嵌套关系是视觉嵌套，不是真正的父子分组。直接生成时应按语义建立真实组和相对坐标，方便成组移动。

9 个图片节点意味着它采用“原生框、文字、连接线＋部分图片”的混合实现。图片中包括本可拆成原生图元的编码器结构或特征序列。不能因为扩展名是 `.drawio`，就声称内部每个元素均可编辑。

新技能采取：**复现这种信息组织和视觉效果，提升关键结构的原生编辑粒度。** 真实照片和复杂局部纹理可以保留；条带、文字、连接、简单层级结构尽量原生化。

## 8. 对旧设计方向的具体修订

| 旧倾向 | 新规则 |
| --- | --- |
| 用很少的框、很少的标签来定义“高级” | 允许较多必要模块和短标签，以层级、间距和可读性判断 |
| 每张图固定两至四个区、十来个标签 | 数量由任务结构决定，不作为硬验收限制 |
| 所有模块都要有前后状态小插画 | 核心算子展开；架构中的常规模块可以保持抽象 |
| 总标题、矩形、嵌套越少越好 | 允许参考式灰标题带、实线分栏与虚线子组，避免无意义重复 |
| 把文字减少到几乎没有 | 中文短标签承担算法身份和消歧，不堆正文段落 |
| 最终转为 PPTX | 直接生成可编辑 Draw.io，不经过生图、图片描摹或 PPT |

总判断：这不是“极简插画风”，而是**框架规整、内部有内容、局部有视觉对象的高信息密度科研图风格**。

## 9. 本版新增的直接生成与颜色约定

当前最终要求是 GPT/Codex 直接写 Draw.io，不再先生成位图。参考中的图片只帮助识别视觉语法，不是每张新图必须有的素材。黑白灰作为底色、框架、文字和大部分连线；淡蓝、淡绿、浅赭等可以小面积表示语义，不强制纯灰度。具体配色和数量由图的职责决定。

## 10. v3：保留参考的组织，修正实用中的松散

用户实际反馈指出生成图空白多、字体小、结构混乱、箭头关联与落点错误。本版不把参考的整张大工作台作为版式，也不复刻其错线。新增结构前置、最终字号预算、内容定框、关系白名单与固定端口。高密度指必要信息在较紧凑空间中清楚呈现，不是机械复制参考宽高、增加框数或缩字。
