# v4 验收：不要把可解析当作正确

## 0. 参考门（正式绘图前，阻断性）

- [ ] 按具体算法与变体检索了原始示意图，不只检索抽象风格。
- [ ] 已实际看清原图，读图注与对应说明；不是只读摘要或 OCR。
- [ ] 有准确 URL、图号／页码与真实查看记录。
- [ ] 各关键机制映射到适用参考；纯风格图没有用来证明机制。
- [ ] 参考与当前算法差异、不可照搬内容已记录。
- [ ] 原创组合有组件参考与当前方法依据，没有伪称网上已有同款。
- [ ] 缺参考／模糊／未核对的关键部分未画成确定结构。
- [ ] references.json 对应当前 topology，未自动刷指纹掩盖改动。

## A. 前置结构门

- [ ] 已读算法材料；不从风格参考猜算法。
- [ ] topology先于scene；每条关系有依据、明确方向和含义。
- [ ] 复杂图比较了两个整体结构，已选择一个主方向和分区方案。
- [ ] 支路、判断、汇合、回路与实际入口出口都有明确安排。
- [ ] 正文字号和最终插图宽度已预算，区域尺寸由内容计算。

## B. 关系门（阻断性）

- [ ] XML与冻结关系表没有多边、漏边、反向边。
- [ ] 未将并行串联、归属转数据流、相关转因果。
- [ ] 真实汇合算子清楚；线交叉没有被画成合流。
- [ ] 分支条件与目标对应；反馈返回真实状态；没有虚构闭环。
- [ ] 节点身份与接口类型对齐；每条关系可读成有依据的一句话。
- [ ] 未通过同步篡改关系表使错误图蒙混通过。

## C. 端点与路线门

- [ ] 有source/target绑定，而非悬空点线。
- [ ] 命名端口对应固定entry/exit点，没有全部挤到同一端口。
- [ ] 非矩形perimeter正确；不是接到不可连接的大容器。
- [ ] 线不穿字、不穿无关模块，箭头正确进入边界。
- [ ] 反馈／跨区走线有明确窄通道；不靠超大间距维持可读。
- [ ] 条件标签属于正确的edge，不是飘在附近的文字。

## D. 紧凑与最终字号门

- [ ] 在实际论文宽度核对字号，不拿编辑器放大图充数。
- [ ] 主标签通常9.5–11 pt，次要8.5–9.5 pt；例外有明确版式依据。
- [ ] 每个显著空洞都有必要职责，或者已经压缩。
- [ ] 框按内容定尺寸；不存在大框中间一个小文字框。
- [ ] 简单阶段收窄；未强迫所有栏等宽等高。
- [ ] 压缩组内、组间空间后再裁外边；不是只裁外框。
- [ ] 没有缩字、加灰底、增无关模块、拉大文字框来伪造密度。

## E. 实际渲染与交互

- [ ] 真实Draw.io导出已执行，且实际打开看过。
- [ ] 在最终目标尺寸观察了全部标签和路线。
- [ ] 修改中文标签、移动模块、移动父组后，绑定端点仍正确。
- [ ] 未执行渲染／看图／交互项目分别写未执行。

`qa-layout.json`的告警允许有理有据地接受；`qa-connections.json`的关系错误不可用美观理由忽略。两者都不能证明原始材料正确。常规两轮后仍有阻断问题，交付为草案并写清，不宣称已完成。
